# SWARM//ZERO 아트 디렉션

## 1. 시각 목표

**어두운 산업 시설, 밝은 전술 신호, 실루엣 우선**을 기준으로 한다.

- 바닥과 구조물은 낮은 채도의 냉각된 회색으로 눌러서 유닛과 탄환보다 눈에 띄지 않게 한다.
- 아군과 유리한 상태는 청록, 목표와 주의는 호박, 적과 피해는 적색으로 통일한다.
- 호드 상황에서는 세부 묘사보다 외곽선, 폭, 진행 방향, 움직임으로 역할을 읽게 한다.
- 모든 에셋은 기하 도형과 독자적인 path로 제작한 벡터다. 원작 게임의 그림, 외부 이미지, 외부 글꼴을 가져오지 않는다.
- 장식보다 정보가 우선이다. 색상만으로 상태를 전달하지 않고 아이콘, 형태, 문자를 함께 사용한다.

- 적색은 아군의 일반 장식이나 단순 선택 상태에 쓰지 않는다. 오류·적대·피해와 혼동되기 때문이다.

## 3. 스프라이트 제작과 통합 규칙

### 캔버스와 방향

- 캐릭터와 적은 `128 × 128` viewBox, 조준선은 `64 × 64` viewBox다.
- 배경 사각형은 넣지 않는다. 투명 영역을 포함한 텍스처 중심은 `(64, 64)`, 조준선 중심은 `(32, 32)`다.
- **모든 유닛의 기본 방향은 오른쪽(+X)이다.** 캐릭터의 바이저와 총구, 적의 머리와 앞다리가 오른쪽을 향한다.
- Phaser 각도 0을 스프라이트 진행 방향과 일치시켰으므로 별도의 90도 보정을 두지 않는다. `setOrigin(0.5)`와 `rotation = atan2(dy, dx)` 조합을 기준으로 한다.
- 원본 비율을 유지하고 정수 또는 균일 배율로 표시한다. 회전 시 가장자리가 잘리지 않도록 텍스처 바깥에 3~6원본 px의 투명 여유를 둔다.
- 물리 반경은 밸런스 값의 단일 원천을 따른다. 그림의 투명 여백이나 다리 끝까지 충돌 영역으로 만들지 않는다. 표시 크기는 충돌 반경과 눈에 보이는 몸통이 어긋나지 않는 범위에서 조정한다.

### 레이어와 움직임

- 플레이어 상체는 `characters/{id}.svg`, 하체는 `characters/{id}-legs-{idle,a,b}.svg`로 구성한다. 하체는 이동 방향, 상체는 조준 방향을 사용해 이동과 조준이 독립적으로 읽히게 한다.
- 무기는 `weapons/{rifle,shotgun,launcher,arc,rail,flame,mines}.svg`로 분리한다. 캐릭터별 표시 크기와 무기별 총구 기준점·반동은 `src/game/visual-config.ts`에서 관리하고, 탄환과 총구 화염도 같은 기준점을 사용한다.
- 이동 프레임은 정지·A·B 세 장으로 제한하고, 적은 기존 스프라이트 풀의 텍스처만 두 장으로 교체한다. 프레임마다 벡터를 다시 그리거나 유닛별 실시간 조명을 만들지 않는다.
- 선택 메뉴 초상화는 게임 내 장갑과 헬멧의 색·명암·형태를 재사용해 같은 인물로 인식되게 한다.

### 소형 화면 판독

- 기본 외곽선은 원본 기준 4~6px, 낮은 명도 배경과 만나는 경계는 한 단계 더 어둡게 한다.
- 몸통은 어둡게·중간·밝게의 세 단계만으로 입체감을 만든다. 필터, 노이즈, 복잡한 그라데이션은 사용하지 않는다.
- 눈이나 작은 패널 선은 보조 신호다. 그것을 지워도 역할이 구분될 만큼 실루엣을 우선한다.
- 최종 검증은 확대 이미지뿐 아니라 실제 게임 표시 크기와 겹친 호드 상황에서 수행한다.

### 캠페인 무기와 효과

| 무기 | 작은 화면에서 우선하는 형태 | 표시 크기 / 총구 / 반동 |
| --- | --- | --- |
| ARC-5 `weapons/arc.svg` | 위아래로 벌어진 두 발사극과 세 개의 청록 코일 | 66×33 / 45 / 3.2 |
| Rail Lance `weapons/rail.svg` | 다른 무기보다 긴 직선 가속 레일과 세 개의 고정 링 | 76×38 / 54 / 7.5 |
| Flame Projector `weapons/flame.svg` | 넓게 벌어진 사다리꼴 노즐과 뒤쪽 연료통 | 68×34 / 46 / 1.1 |
| MX-8 `weapons/mines.svg` | 짧고 낮은 총열과 네 칸 회전 탄창 | 60×30 / 37 / 4.2 |

- `effects/chain.svg`는 192×48의 꺾인 가지형 전기 Arc, `effects/rail.svg`는 256×32의 직선 이중 궤적, `effects/flame.svg`는 192×128의 넓은 원뿔이다. 셋 모두 왼쪽 중앙이 시작점이므로 `setOrigin(0, 0.5)`와 진행 방향 회전을 사용한다.
- chain은 대상 사이 거리만큼 X만 늘리고, rail은 실제 충돌로 계산한 궤적 끝까지만 그린다. flame은 시야와 피해 판정과 같은 방향·길이를 쓰되 장식용 화염이 판정 밖의 적을 가리지 않게 짧게 유지한다.
- `effects/mine.svg`는 납작한 팔각 압력 지뢰, `effects/coolant.svg`는 세로 육각 셀과 십자 냉각 무늬, `effects/fuse.svg`는 가로 브리지와 네 개의 단자다. 색을 지워도 원형 보급 상자나 서로 다른 수집물과 구분되어야 한다.
- 효과 원본과 생성 fallback은 모두 `CAMPAIGN_TEXTURES.effects`의 같은 텍스처 키를 쓴다. 실시간 광원, SVG 필터, 적별 필터는 사용하지 않고, 풀 안에서 알파·크기·수명만 조절한다.

## 4. 산업 시설 환경

- 기본 바닥은 `#0B1218`~`#101B22`, 패널 경계는 `#1B2A31` 범위에서 낮은 대비로 유지한다. `environment/floor.svg`를 반복 타일로 사용하고 구역별 정적 색 레이어를 얹는다.
- 바닥 패널은 큰 단위로 나누고 이음새·볼트·배관은 일부에만 배치한다. 모든 타일에 동일한 고대비 무늬를 넣지 않는다.
- 벽과 이동 불가 구조물은 바닥보다 한 단계 밝은 상면과 어두운 측면, 짧은 접촉 그림자로 구분한다. `environment/bed.svg`는 프레임·매트리스·베개·고정대, `console.svg`는 화면·버튼·측면 프레임이 읽혀야 한다.
- 남서 의료 구역, 중앙 정화 구역, 동쪽 중계기, 북서 승강기는 전용 사물과 낮은 대비의 바닥 표시로 구분한다. `environment/vent.svg`, `pipe.svg`, `elevator.svg`, `relay.svg`, `decal.svg`를 사용한다.
- medbay는 `environment/decal-medbay.svg`의 의료 십자와 점선, reactor는 `decal-reactor.svg`의 분할 containment ring, hive는 `decal-hive.svg`의 유기적 성장선을 사용한다. 세 데칼은 `CAMPAIGN_TEXTURES.decals`로 미리 로드하고 800px 정적 청크에만 굽는다.
- 테마 색조는 바닥과 데칼에 낮은 불투명도로 제한한다. medbay의 청록, reactor의 호박, hive의 적갈색이 적·아군·목표의 고정 색 의미를 바꾸지 않게 한다.
- `src/game/facility.ts`가 환경을 여섯 개의 800px 정적 RenderTexture 청크로 생성한다. 맵 전체를 하나의 고해상도 이미지로 만들지 않고 실시간 조명·필터를 추가하지 않는다.
- `OBSTACLES`의 충돌 사각형과 구조물의 보이는 경계를 맞춘다. 통행 가능한 곳을 그래픽으로 막거나 통행 불가 구역을 바닥처럼 꾸미지 않는다.
- 호박 해치 스트라이프는 잠재적 위험이나 작동 구역에만 쓴다. 실제 피해가 활성화되면 적색 점등과 경고 아이콘을 추가한다.
- 목표 주변의 바닥 무늬와 파편 밀도를 낮춰 마커와 유닛이 묻히지 않게 한다. 테마 데칼도 수집물·지뢰·방어 범위 아래에서 같은 명도로 유지한다.
- 전투 효과는 짧고 밝게 유지하되 잔상을 길게 남기지 않는다. 아군 발사는 청록/백색, 적대 공격은 적색 계열로 구분한다.

## 5. 게임 HUD와 대시보드

### 여백과 표면

- 4px 기반 간격을 사용한다: `4, 8, 12, 16, 24, 32, 48`.
- 데스크톱 게임 HUD의 화면 안전 여백은 24px을 권장하고, 좁은 화면에서는 16px까지 줄인다.
- HUD 패널의 안쪽 여백은 12~16px, 대시보드 카드는 16~24px, 카드 사이는 16px을 기본으로 한다.
- 기본 표면은 불투명에 가까운 `#101820`, 1px 경계는 `#2A3B43`이다. 전투 장면 위에서는 배경이 비치는 정도를 높이지 말고 문자 대비를 우선한다.
- 모서리는 4~8px로 절제하고, 강조 패널에는 두꺼운 발광 대신 2~4px의 청록 또는 호박 포커스 선을 사용한다.
- HUD는 중앙 전투 영역을 가리지 않게 모서리로 배치하고, 목표 정보와 위협 경고는 서로 겹치지 않는 별도 레이어로 둔다.

### 타이포그래피

- 외부 글꼴 없이 `system-ui, -apple-system, "Segoe UI", "Noto Sans KR", sans-serif`를 사용한다.
- 수치·탄약·타이머·로그에는 `ui-monospace, "SFMono-Regular", Consolas, monospace`와 `font-variant-numeric: tabular-nums`를 권장한다.
- 기준 크기는 보조 12px, 본문 14~16px, 패널 제목 18~20px, 화면 제목 28~32px, 결과 수치 40px다.
- 한국어 본문 줄 높이는 1.5~1.65, 짧은 제목은 1.25~1.4로 설정한다.
- 본문은 400~500, 제목과 핵심 수치는 600~700을 사용한다. 영문 약어가 아닌 한국어 문장을 전각 대문자처럼 과도하게 꾸미지 않는다.
- 탄약은 `현재 / 예비`처럼 역할이 보이는 레이블과 함께 표시하고, 숫자 색만으로 재장전 상태를 설명하지 않는다.

### 모바일 컨트롤

- 전투는 가로 화면을 기준으로 하고 세로에서는 전투를 일시정지한 회전 안내를 표시한다.
- 이동 스틱은 왼쪽 아래, 사격은 오른쪽 아래, 재장전은 그 위에 배치한다. 무기와 탄약은 하단 중앙, HP·목표·일시정지는 상단에 배치해 두 엄지의 조작 영역과 정보 영역을 분리한다.
- 일곱 무기를 일곱 개의 작은 버튼으로 나열하지 않는다. **이전 무기 / 현재 무기 / 다음 무기** 세 컨트롤을 각각 최소 48px로 유지하고 현재 무기는 이름과 탄약을 함께 표시한다.
- 주요 터치 목표는 최소 48px, 이동 스틱은 약 112~128px를 기준으로 하고 `env(safe-area-inset-*)`로 노치와 홈 표시줄을 피한다.
- 컨트롤은 반투명한 청록·적색·호박 신호를 사용하되 전투 장면과 HP·탄약·목표를 가리지 않는다. 눌린 상태는 색과 형태 변화로 확인한다.
- 자동 조준선은 현재 대상 위치를 따라가고 대상이 없으면 마지막 방향의 플레이어 앞에 둔다. 조준 여부와 실제 발사 여부를 혼동하지 않게 사격 버튼의 눌림 상태를 분리한다.

### 대시보드

- 대시보드도 같은 토큰을 쓰되 게임보다 장식과 발광을 줄이고 표와 상태 판독에 집중한다.
- 상태 칩에는 아이콘과 `정상`, `주의`, `오류` 같은 텍스트를 함께 넣는다. 색 점 하나만으로 상태를 표현하지 않는다.
- 테이블은 행 높이 40~44px, 열 사이 16px을 기준으로 하고 수치 열은 오른쪽 정렬한다.
- 키보드 포커스는 2px 이상의 `--swarm-teal` 외곽선과 2px 간격으로 표시한다. 포커스를 제거하지 않는다.

## 6. 목표·위험·결과 상태

### 목표

- 목표의 기본 형태는 **호박 마름모 + 어두운 받침 + 짧은 레이블**이다. 적의 붉은 둥근 실루엣과 형태로 구분한다.
- `mission.label`을 우선 표시하고, 진행 중에는 `현재 / 목표`와 막대를 함께 제공한다. 막대는 호박, 완료는 청록 체크와 `완료` 문자로 바꾼다.
- 화면 밖 목표는 안전 여백 안쪽에 방향 화살표를 고정하고 거리를 덧붙인다. 화살표만 보고 방향을 추측하게 하지 않는다.
- 침투·방어·탈출은 같은 목표 체계를 유지하되 레이블과 보조 아이콘으로 구분한다. 단계마다 팔레트를 바꾸지 않는다.

### 단계 배너와 해금

- `STAGE XX START`와 `STAGE XX CLEAR`는 어두운 중립 표면, 얇은 청록 또는 호박 경계, 단계 이름과 한 줄 목표를 사용한다. 별도의 큰 배너 이미지는 두지 않는다.
- 가로 모바일에서는 상단 HP·목표와 하단 무기 컨트롤 사이의 안전 영역에 배너를 제한하고, 제목 20~24px·본문 12~14px까지 줄인다. 컨트롤 위에 해금 버튼이 겹치지 않게 `env(safe-area-inset-*)`를 적용한다.
- 해금은 무기 실루엣과 `ARC-5`, `Rail Lance` 같은 이름을 함께 보여준다. 색 점멸만으로 보상을 알리지 않으며, 최종 `MISSION COMPLETE`도 `STAGE 10 CLEAR`와 별도 상태로 읽히게 한다.

### 위험과 피해

- 위험은 **적색 삼각 경고 또는 톱니형 테두리 + 위험 원인 문자**로 표현한다. 목표의 마름모와 형태를 달리한다.
- 피해 방향은 해당 가장자리의 짧은 적색 호로 보여주고, 화면 전체를 붉게 덮는 효과는 낮은 불투명도와 짧은 시간으로 제한한다.
- HP가 낮으면 붉은색뿐 아니라 경고 아이콘과 `HP 현재 / 최대` 수치를 함께 둔다. 지속적인 화면 깜빡임으로 알리지 않는다.
- 재장전·탄약 부족은 각각 진행 표시와 `재장전`, `탄약 없음` 문자를 사용한다. 탄약 부족을 일반 오류처럼 크게 울리지 않게 한다.
- 경고가 한 번에 여러 개면 가장 즉각적인 피해 원인을 우선하고 나머지는 합친다. 경고끼리 점멸 경쟁을 하지 않는다.

### 일시정지·승리·사망

- 일시정지는 중립 표면과 `일시정지` 제목을 사용한다. 위험색으로 처리하지 않는다.
- 승리와 임무 완료는 청록 체크, 사망과 실패는 적색 파손 아이콘을 사용하고 결과를 문자로 명시한다.
- 색을 구분하기 어려운 사용자도 아이콘·레이블·막대 위치만으로 동일한 상태를 이해할 수 있어야 한다.
- 점멸은 초당 3회를 넘지 않게 하고, 반복 펄스와 화면 흔들림은 줄이기 설정을 고려한다.

## 7. 조준선과 인터랙션

- 기본 조준선은 64px 원본을 32~40px로 표시하고 포인터 중심에 맞춘다. UI 이벤트를 가로채지 않도록 `pointer-events: none`을 적용한다.
- 기본 상태는 청록이다. 타격 확인에는 짧은 호박 점멸, 발사 불가에는 적색과 형태 변화를 추가할 수 있다. 단순 호버를 실제 조준 성공처럼 표현하지 않는다.
- 조준선 아래의 적과 바닥이 보이도록 중심을 비워 두고, 상태 효과가 조준점을 완전히 가리지 않게 한다.
- 커서를 숨기는 게임 화면과 표준 커서가 필요한 메뉴·대시보드를 구분한다.

## 8. 산출물과 통합 확인

- `public/assets/characters/`: 두 상체와 여섯 하체 프레임, 8장
- `public/assets/enemies/`: 세 기본 적과 elite/Alpha Brute의 기본·보행 프레임, 10장
- `public/assets/weapons/`: 기존 세 무기와 ARC-5, Rail Lance, Flame Projector, MX-8, 7장
- `public/assets/environment/`: 기존 시설물과 바닥 표시 9장, 세 테마 데칼 3장, 총 12장
- `public/assets/effects/`: chain, rail, flame, mine, coolant, fuse, 6장
- `public/assets/portraits/`: scout와 heavy 초상화, 2장
- `public/assets/ui/crosshair.svg`: 1장

총 46개 SVG 중 `scripts/generate-art.mjs`가 45개를 생성하고 기존 수작업 조준선 1개를 유지한다. 모든 SVG는 자체 완결형 XML이며 스크립트, 외부 URL, 래스터 링크, 외부 글꼴을 포함하지 않는다. 통합 시 Vite base 경로, 중심 또는 왼쪽 중앙 원점, 오른쪽 기준 회전, 하체·상체·무기의 조합, 총구 위치, 실제 표시 크기, 호드 겹침, 신규 텍스처의 preload와 생성 fallback, 목표·위험 상태의 문자 레이블을 함께 확인한다.
